## Intended Outcome

A compact property bar sits above the desktop tool strip and shows the most-used properties for whatever is selected — fill, stroke, corner radius, opacity, position — changing with the selection type. The full Properties panel remains untouched and authoritative for deep edits.

## The decision this packet exists to honour

Agreed 2026-08-12: the contextual bar and the Properties panel **both stay**, and both read and write **one shared property model**. They must not be able to diverge.

**Good news found during expansion: that shared model already exists.** `@open-pencil/vue` exposes headless property composables — `PropertyListRoot.vue` uses `useEditorPropertyList(propKey)`, which already provides:

```ts
context.active    // Ref<boolean>  — does this property apply to the selection
context.items     // Ref<T[]>      — current values
context.isMixed   // Ref<boolean>  — multi-select mixed values, already solved
context.actions   // { add, remove, update, patch, toggleVisibility, reorder }
```

So the correct implementation is: **bind the new bar to the same headless composables the panel already uses.** Do not create a Pinia store, a shared ref, a sync watcher, or an event bus. If you find yourself writing code to *copy* a value from the panel to the bar, you have taken the wrong approach — stop and re-read this section.

## Placement decision

The Canva reference puts this bar at the top. **OpenPotlood puts it at the bottom** — the tool strip is bottom-centred and T-031d just consolidated the top chrome row into the tab bar. A top bar would re-add the band T-031d removed.

- Render as a **separate row directly above** the `DesktopToolbar` strip, sharing its horizontal centring.
- Gap between the two rows: `8px` (`mb-2` on the property row).
- The property row and tool strip are **visually distinct containers**, not merged into one pill.
- Cap the row at `calc(100vw - 32px)`; overflow horizontally with `overflow-x-auto scrollbar-thin` rather than wrapping, hiding controls, or shrinking the tool strip.
- When nothing is selected the row is **not rendered at all** (not an empty container).

## Contents by selection type

Show only what applies. Derive applicability from `context.active` on each property, never from a hand-written type switch.

| Selection | Controls, in order |
| --- | --- |
| Single shape / frame | Fill swatch · Stroke swatch · Corner radius · Opacity · Position (X/Y/W/H collapsed behind one button) |
| Text | Font family · Size · Weight · Colour · Alignment · Opacity |
| Image | Opacity · Corner radius · Position |
| Multi-select | Common applicable controls only, each showing mixed state via `isMixed` |
| Nothing selected | Row not rendered |

- Mixed values must use whatever the existing sections already render for `isMixed` — find it and match it. Do not invent a "Mixed" string.
- Anything not in the table stays panel-only. This bar is a **common subset**, not a second full property editor.

## Visual Contract — binding

Container, matching `DesktopToolbar.vue` exactly:

```
rounded-lg border border-border/80 bg-panel/95 p-1 shadow-lg backdrop-blur-md
```

| Element | Required classes |
| --- | --- |
| Row wrapper | `absolute bottom-5 left-1/2 z-10 flex -translate-x-1/2 flex-col items-center` (the property row and tool strip stack inside this) |
| Property row | `flex items-center gap-1` + container string above |
| Group separator | `mx-1 h-4 w-px bg-border` |
| Control height | `h-(--spacing-control)` — the token is `24px`. Do not hardcode `h-6`. |
| Labels | `text-[11px] text-muted` |
| Values / inputs | `text-xs text-surface` |
| Icons | `size-3.5` |
| Popovers | `usePopoverUI()` from `components/ui/popover.ts` |

### Banned List — do not do any of these

- No literal colour — no hex, `rgb()`, `hsl()`, or Tailwind palette names (`bg-slate-700`, `text-neutral-300`). Only semantic tokens: `bg-panel`, `bg-panel-field`, `text-surface`, `text-muted`, `border-border`, `bg-hover`, `text-accent`.
- No font-size class other than `text-xs` or `text-[11px]`. Never `text-sm`, `text-base`, `text-lg`.
- No radius other than `rounded-md` or `rounded-lg`.
- **No new state.** No Pinia store, no module-level `ref`, no `watch` that copies a value between the bar and the panel, no `provide/inject` of property values, no event bus.
- No rebuilt inputs. Reuse `AppInput`, `AppSelect`, `FillSwatch`, `SegmentedControl`, `IconButton`.
- No edits to `App/src/app.css`, no new `tv()` recipe, no `@apply`, no new global CSS.
- No new npm dependency.
- No changes to `PropertiesPanel` behaviour, layout or contents.
