# T-071 — Auto-layout gap direct drag

Task ID: T-071
Packet state: Ready
Depends on: T-046, T-039 (Done)
Related: T-010 (guides only; do not change)

## Intended Outcome

When one horizontal or vertical auto-layout frame is selected, drag its visible on-canvas gap marker to change `itemSpacing` continuously. It must work at zero spacing as well as positive spacing, be constrained to the layout axis, and create one undo entry on release. Double-click editing remains available.

## Verified Starting State

- `App/packages/core/src/canvas/overlays/auto-layout-hover.ts` — `gapRects()` has the same `itemSpacing <= 0` early-return (line 129), so the marker isn't drawn at zero either. Both must change together or the drag target becomes invisible-but-draggable or visible-but-undraggable.
- `App/packages/vue/src/canvas/useCanvasInput.ts` — pointer-down order today (`onMouseDown`, from ~line 447) is: commit any open padding/spacing scrub edit → `startPageGuideDrag` → `SHAPE_BUILDER` region hit-test → `handleToolMouseDown` (normal selection/tool dispatch). There is no drag-state branch for spacing; only `startAutoLayoutSpacingEdit()` exists and it only fires from `onDblClick`. No `padding-drag` type exists either (padding is double-click-only, out of scope here).
- `App/packages/vue/src/shared/input/types.ts` — `DragState` union (lines 195-213) has no spacing-drag variant. The closest existing pattern is `DragRadius` (`App/packages/vue/src/shared/input/radius.ts`): `tryStartXxx` → `applyXxxDrag` (live preview via `editor.graph.updateNodePreview` + `editor.requestRepaint()`) → `commitXxxDrag` (`editor.updateNode(original)` then `editor.updateNodeWithUndo(final, label)`) → `cancelXxxDrag` (`editor.updateNode(original)`). Wired into `useCanvasInput.ts` at: `onMouseMove` dispatch (~line 570), `onMouseUp` dispatch (~line 626), Escape handler (~line 695).
- Constants already defined in `App/packages/core/src/constants.ts`: `AUTO_LAYOUT_HOVER_GAP_REGION_TOLERANCE = 12`, `AUTO_LAYOUT_HOVER_TICK_HIT_TOLERANCE = 8`.

## Scope and Acceptance Criteria

1. **Zero-gap hit target (`auto-layout-hover.ts`, vue package).** In `resolveSpacingHover`, drop the `node.itemSpacing <= 0` bail-out; when `gapEnd === gapStart` (adjacent children touching), still return `{ kind: 'spacing', index: i }` when the cursor's main-axis coordinate is within `AUTO_LAYOUT_HOVER_GAP_REGION_TOLERANCE` of that shared boundary point. Keep the existing `spacing-value` tick behavior unchanged (it only makes sense for `itemSpacing > 0`, since there's no positive gap to place a value tick in). Do not enlarge the hit box beyond the existing tolerance — must not steal clicks meant for the children on either side (existing `resolveChildrenHover` still runs after spacing in `resolveAutoLayoutHover`'s `??` chain, so keep spacing's win-priority as-is; add a test proving a click just past the tolerance band still resolves to `children`).
2. **Zero-gap visual marker (`auto-layout-hover.ts`, core package).** In `gapRects`, when `gapEnd <= gapStart`, emit a zero-width rect centered on the boundary (main-axis span `[gapStart, gapStart]`, i.e. width/height `0` on the layout axis) instead of skipping. In `drawStripedRect`, a `0`-width/height rect currently early-returns (`if (width <= 0 || height <= 0) return`) — leave that guard for the fill/stripes (nothing to fill at zero width), but change `drawSpacingHover` so the hover-active state (`hover.kind === 'spacing'`) draws a thin indicator line (reuse `drawVerticalTick`/`drawHorizontalTick` at the boundary point, same magenta color) even when the rect has no area, so the affordance is visible before the user starts dragging.
3. **New drag type `spacing-drag`.** Add to `App/packages/vue/src/shared/input/types.ts`:
   ```ts
   export interface DragSpacingDrag {
     type: 'spacing-drag'
     nodeId: string
     axis: 'HORIZONTAL' | 'VERTICAL'
     startCursor: number   // cx or cy at pointer-down, matching axis
     original: number      // node.itemSpacing at pointer-down
   }
   ```
   Add it to the `DragState` union.
4. **New helper module `App/packages/vue/src/shared/input/spacing-drag.ts`** mirroring `radius.ts`'s shape:
   - `tryStartSpacingDrag(cx, cy, editor): DragSpacingDrag | null` — calls `resolveAutoLayoutHover(cx, cy, editor)`, returns `null` unless `hover.kind === 'spacing'`; reads the node's `layoutMode` and `itemSpacing`; records `startCursor` as `cx` for `HORIZONTAL`, `cy` for `VERTICAL`.
   - `applySpacingDrag(d, cx, cy, editor): void` — delta = `(axis === 'HORIZONTAL' ? cx : cy) - d.startCursor`, converted through `editor.state.zoom` the same way other drag maths in this file do (check `applyResize`/`calculateRadiusFromLocalPointer` for the existing zoom-normalization convention before assuming raw pixel deltas are already scene units — `cx`/`cy` from `getCoords` are already scene-space per other handlers, so likely no extra zoom division needed; confirm against `getCoords` in `useCanvasInput.ts` before writing the math). Next value = `Math.max(0, Math.round(d.original + delta))`. Push a preview via `editor.graph.updateNodePreview(d.nodeId, { itemSpacing: next })` + `editor.requestRepaint()` (matching `applyRadiusDrag`), not `editor.updateNode`, so intermediate frames don't each need their own undo bookkeeping.
   - `commitSpacingDrag(d, editor): void` — read the live previewed value off the node, restore `d.original` via `editor.updateNode`, then `editor.updateNodeWithUndo(d.nodeId, { itemSpacing: finalValue }, 'Update item spacing')` (reuse the exact label already used by `commitAutoLayoutSpacingEdit` in `useCanvasInput.ts` for consistency in the undo stack). No-op (skip the undo call) if final equals original.
   - `cancelSpacingDrag(d, editor): void` — `editor.updateNode(d.nodeId, { itemSpacing: d.original })`.
5. **Wire into `useCanvasInput.ts`:**
   - In `onMouseDown`, add a `tryStartSpacingDrag` check before `handleToolMouseDown` is called (same tier as `startPageGuideDrag`/the shape-builder region check) so a pointer-down on the gap marker claims the drag before normal selection runs; on success call `setDrag(...)`, `e.preventDefault()`, `e.stopPropagation()`, `return`.
   - In the `onMouseMove` drag dispatch (the `if (d.type === '...')` chain around line 570), add `if (d.type === 'spacing-drag') { applySpacingDrag(d, cx, cy, editor); return }`.
   - In `onMouseUp` (around line 626), add `else if (d.type === 'spacing-drag') commitSpacingDrag(d, editor)`.
   - In the Escape `keydown` handler (around line 695), add `else if (drag.value.type === 'spacing-drag') cancelSpacingDrag(drag.value, editor)` alongside the existing `radius`/`progressive-blur`/`gradient-handle` branches, then `drag.value = null; cursorOverride.value = null`.
   - The window `pointerup` listener (line 678) already calls `onMouseUp` for any active `drag.value`, so releasing outside the canvas commits through the same path — no separate wiring needed there.
   - Leave `startAutoLayoutSpacingEdit`/`onDblClick`, the floating number editor, padding controls, and auto-layout reordering untouched.
