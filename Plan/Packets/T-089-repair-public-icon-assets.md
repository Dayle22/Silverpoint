## Fixed Decisions

1. **Copy the real bytes; do not recreate symlinks.** This is a local-only Windows project with no Git workflow (`App/AGENTS.md`), so a symlink would break again on any copy and provides no benefit. Each `public/` file becomes a byte-for-byte copy of its `desktop/icons/` target.
2. **Copy, never move.** `desktop/icons/` is Tauri's bundle icon source (`desktop/tauri.conf.json`); removing or relocating anything there would break the desktop bundle.
3. **`apple-touch-icon.png` gets `icon.png` (11,133 bytes) as-is.** No resizing: the current pointer names that exact target, no build step resizes it today, and adding an image-processing step would need a new dependency (Banned List).
4. **No new asset, no rename, no new reference.** Every path in `index.html` and `AppMenu.vue` stays exactly as written; only the file contents change.
5. **`favicon.ico` keeps `icon.ico`'s full 104,917 bytes.** It is a multi-resolution ICO; shrinking it is out of scope and unverifiable here.

## Implementation Steps

**Step 1 — Pre-flight.** Confirm the breakage still matches the Verified Starting State before copying, so a later repair is not undone:

```bash
cd App && for f in public/favicon-32.png public/favicon-128.png public/favicon.ico public/apple-touch-icon.png; do printf "%s %s -> " "$(stat -c%s "$f")" "$f"; head -c 40 "$f"; echo; done
```

Expected: four lines of `25`–`28` bytes each printing a `../desktop/icons/...` path. If any file is already binary (its size is in the hundreds or thousands and the content is unreadable), that file is already repaired — skip it in Step 2 and say so in the report.

**Step 2 — Replace the four files with their real targets.** From `App/`:

```bash
cd App && cp desktop/icons/32x32.png public/favicon-32.png && cp desktop/icons/128x128.png public/favicon-128.png && cp desktop/icons/icon.ico public/favicon.ico && cp desktop/icons/icon.png public/apple-touch-icon.png
```

(PowerShell equivalent, if the Bash tool is unavailable: four `Copy-Item -Path desktop\icons\<source> -Destination public\<target> -Force` calls with the same pairs. Do not use `New-Item -Force` on these paths.)

**Step 3 — Verify the bytes landed.** From `App/`:

```bash
cd App && for f in public/favicon-32.png public/favicon-128.png public/apple-touch-icon.png; do printf "%s %s " "$(stat -c%s "$f")" "$f"; head -c 4 "$f" | xxd -p; done && stat -c%s public/favicon.ico
```

Expected sizes: `favicon-32.png` 687, `favicon-128.png` 2546, `apple-touch-icon.png` 11133, `favicon.ico` 104917. The three PNGs must each start with `89504e47`.

**Step 4 — No test files.** There is no existing asset-integrity test and this packet adds none; the browser check in **Integration Check** is the proof.
