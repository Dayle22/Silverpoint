# Regenerable Artefacts

This document records directories and artefacts within `App/` that are transient build or test outputs rather than persistent source files. Because the project does not use a `.gitignore` file, these paths may reappear during development and should be recognised as safe, regenerable outputs rather than committed source or debris to investigate.

## Regenerable Directories and Files

1. `dist/`
   - **Origin**: Frontend production build directory.
   - **Regeneration**: Generated by `vite build` (or `bun run build`).
   - **Usage**: Tauri consumes this directory as the `frontendDist` target during `tauri build` and production package creation.

2. `test-results/`
   - **Origin**: Playwright test runner bookkeeping and test execution results (including `.last-run.json`, traces, and test output).
   - **Regeneration**: Automatically generated or updated whenever Playwright runs (`playwright test` or `bun test:browser`).

3. `output/playwright/` (or `output/`)
   - **Origin**: Playwright test reports or custom output paths.
   - **Regeneration**: Generated when tests are configured to write reports or screenshots to the output folder.

## Ad-Hoc Scripts and Debug Artefacts

Ad-hoc debug scripts, one-off repro files, and temporary logs belong in an agent session's scratch area or under `App/tests/` as asserted test cases, and must never be committed directly into `App/` root or arbitrary folders (such as `_to_delete/`).
